Issues the DTE of a sale that already exists — for example one created without `dte`, or one whose DTE failed when it was created with [`POST /v1/ecommerce/sales`](/dev/endpoints/ecommerce-sales-create).

## Endpoint

```
POST https://api.keebai.com/v1/ecommerce/sales/{id}/dte
```

## Required scope

`ecommerce:invoicing:issue`

<Note>
  **The scope comes from your role.** Minting a token with `ecommerce:invoicing:issue` requires the permission to issue DTE in your Keebai role, unless you are the company owner or a superuser. See [scopes](/dev/scopes#scopes-are-independent-from-role-permissions).
</Note>

## Headers

| Header | Required | Value |
|---|---|---|
| `Authorization` | Yes | `Bearer kbai_pk_<token>` |
| `Content-Type` | Yes | `application/json` |

## Path parameters

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | `string` | Yes | `ObjectId` of the sale. |

## Body

| Field | Type | Required | Description |
|---|---|---|---|
| `type` | `number` | Yes | `39` boleta, `41` boleta exenta, `33` factura, or `34` factura exenta. |
| `receiver` | `object` | Conditional | `rut`, `legal_name`, `activity`, `address`, `commune`, `email?`. Required for a factura (`33`, `34`). |
| `save_receiver` | `boolean` | No | Save the receiver for later documents. |

## Example request

<CodeGroup>

```bash curl
curl -X POST https://api.keebai.com/v1/ecommerce/sales/65e4f5a6b7c8d9e0f1a2b3c4/dte \
  -H "Authorization: Bearer kbai_pk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "type": 33,
    "receiver": {
      "rut": "76123456-7",
      "legal_name": "Comercial Ejemplo SpA",
      "activity": "Venta al por menor",
      "address": "Av. Libertador 1234",
      "commune": "Santiago",
      "email": "facturas@ejemplo.cl"
    },
    "save_receiver": true
  }'
```

```js JavaScript
const response = await fetch(
  `https://api.keebai.com/v1/ecommerce/sales/${saleId}/dte`,
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.KEEBAI_API_TOKEN}`,
      "Content-Type": "application/json",
    },

  },

```

```python Python
import os, requests

resp = requests.post(
    f"https://api.keebai.com/v1/ecommerce/sales/{sale_id}/dte",

    json={"type": 39},
    timeout=30,

resp.raise_for_status()

```

## Response

### 200 OK

The call answers with what was issued and what failed. A DTE that cannot be issued comes back in `failed` with its reason, not as an HTTP error.

```json
{
  "issued": [
    {
      "sale_id": "65e4f5a6b7c8d9e0f1a2b3c4",
      "type": 33,
      "folio": 8211,
      "document_id": "6653e4f5a6b7c8d9e0f1a2b4",
      "status": "uploaded"
    }
  ],
  "failed": []
}
```

```json Failed
{
  "issued": [],
  "failed": [
    {
      "sale_id": "65e4f5a6b7c8d9e0f1a2b3c4",
      "reason": "unpaid"
    }
  ]
}
```

| Field | Type | Description |
|---|---|---|
| `issued[]` | `object[]` | Documents issued: `sale_id`, `type`, `folio`, `document_id`, `status`. |
| `failed[]` | `object[]` | Documents not issued: `sale_id`, `reason` (the error code), `message?`. |

### Failure reasons

| `reason` | Meaning |
|---|---|
| `already_issued` | The sale already has its DTE. |
| `unpaid` | The sale is not fully paid. Only a paid sale can be invoiced. |
| `receiver_required` | A factura needs `receiver`. |
| `not_completed` | The sale is not completed. |
| `deleted` | The sale was deleted. |
| `exempt_type_required` | The sale has no taxed lines, so it needs an exempt type (`41` or `34`). |
| `taxed_lines` | The sale has taxed lines, so an exempt type does not apply. |
| `no_lines` | The sale has no lines to invoice. |
| `too_many_items` | The sale has more lines than the document allows. |
| `amount_invalid` | The sale's amount cannot be invoiced. |

### 400 Bad Request

The body does not match the schema, or `dte_issuer_missing`: the company has not registered its DTE issuer yet. That is configured in the portal.

### 401 Unauthorized

Missing, invalid, revoked, or expired token.

### 403 Forbidden

The token does not have the `ecommerce:invoicing:issue` scope.

### 404 Not Found

No sale with that id, or it belongs to a different company.

### 502 Bad Gateway

`ECOMMERCE_UPSTREAM_ERROR` — the ecommerce service could not answer.

## Operational notes

- **Branch on `failed`, not only on the status.** A request that did not issue anything can still succeed at the HTTP level.
- **`already_issued` makes retries safe.** Calling again for a sale that already has its DTE does not issue a second one; it comes back in `failed` with that reason.
- **Check the types first.** [`GET /v1/ecommerce/invoicing/types`](/dev/endpoints/ecommerce-invoicing-types) tells you which `type` values the company can issue today.
- **Read the issued documents** with [`GET /v1/ecommerce/sales/{id}/documents`](/dev/endpoints/ecommerce-sale-documents).
