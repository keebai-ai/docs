Turns a full stamps card into a membership in another program. A stamps program can name the program it upgrades to in `rules.stamps.upgrades_to_program_id`. For example, a Club card with six visits can be exchanged for the VIP card. When the card is complete, this call deletes it, including its movements, and gives the customer the target membership.

The customer's wallet card follows automatically. If the target membership had no pass yet, the same card in Apple Wallet or Google Wallet turns into the target program's card, with its design and data. If the customer already had a pass for the target program, the old card is voided, because Apple and Google do not let a server remove a pass from a phone.

## Endpoint

```
POST https://api.keebai.com/v1/loyalty/memberships/{id}/upgrade
```

## Required scope

`loyalty:write`

## Headers

| Header | Required | Value |
|---|---|---|
| `Authorization` | Yes | `Bearer kbai_pk_<token>` |

## Path parameters

| Parameter | Type | Description |
|---|---|---|
| `id` | `string` | The `ObjectId` of the stamps membership being handed in. |

The request has no body.

<CodeGroup>

```bash curl
curl -X POST https://api.keebai.com/v1/loyalty/memberships/6650aaaa1111bbbb2222cccc/upgrade \
  -H "Authorization: Bearer kbai_pk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

```js JavaScript
const response = await fetch(
```


## Response

### 201 Created

| Field | Description |
|---|---|
| `upgraded_card` | The card that was handed in, as it was before the upgrade. It no longer exists. |
| `membership` | The membership in the target program. It is new, or the customer's existing one if they already had it. |
| `entry` | The ledger entry recorded on the target membership: `kind: "adjust"`, `amount: 0`, `source: "upgrade"`, with `ref` set to the id of the program the card came from. |

```json
{
  "upgraded_card": {
    "_id": "6650aaaa1111bbbb2222cccc",
    "program_id": "6650a1b2c3d4e5f6a7b8c9d0",
    "status": "active",
    "stamps_count": 6
  },
  "membership": {
    "_id": "6650bbbb2222cccc3333dddd",
    "program_id": "6650a1b2c3d4e5f6a7b8c9d1",
    "status": "active",
    "stamps_count": 0
  },
  "entry": {
    "_id": "6650dddd3333eeee4444ffff",
    "membership_id": "6650bbbb2222cccc3333dddd",
    "kind": "adjust",
    "metric": "stamps",
    "amount": 0,
    "balance_after": 0,
    "source": "upgrade",
    "ref": "6650a1b2c3d4e5f6a7b8c9d0",

  }

```

Membership objects are abbreviated here. They have the same shape as [GET /v1/loyalty/memberships/{id}](/dev/endpoints/loyalty-membership-get).

### 400 Bad Request

The program is not a stamps program, or it has no `upgrades_to_program_id`.

### 401 Unauthorized

The token is missing, invalid, revoked, or expired.

### 403 Forbidden

The token does not have the `loyalty:write` scope.

### 404 Not Found

There is no membership with that id in your company, or the target program no longer exists.

### 409 Conflict

The card is not full yet, the card is not active (for example, it was already handed in), or the target program is not active. Nothing changes.

## Operational notes

- **The upgrade happens only once.** Claiming the full card is a single conditional update. If two calls race, one succeeds and the other gets `409`.
- **The old card is gone.** It is deleted the same way as [DELETE /v1/loyalty/memberships/{id}](/dev/endpoints/loyalty-membership-delete).
- **Partial redemptions use the ledger.** To pay out what a card has accumulated without upgrading, record `kind: "redeem"` with [POST .../ledger](/dev/endpoints/loyalty-ledger-record). With `reset_on_redeem`, the card goes back to `0`.
- **The cash value of a stamp is `rules.stamps.value_per_stamp`.** The wallet binding `{{stampsValue}}` shows the stamp count multiplied by that value, for example the cashback accumulated so far.
