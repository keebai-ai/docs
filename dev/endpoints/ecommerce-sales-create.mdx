Creates a sale in Keebai. Stock is deducted from the branch, commissions are calculated, and, if you pass `dte`, the electronic tax document is issued right after.

A `type: "internal"` sale records internal consumption instead: products taken out of stock for the business's own use, with no payments and no DTE.

## Endpoint

```
POST https://api.keebai.com/v1/ecommerce/sales
```

## Required scope

`ecommerce:sales:write`

Sending `dte` also needs `ecommerce:invoicing:issue`. Without it the request fails with `403 INSUFFICIENT_SCOPE` before the sale is created.

<Note>
  **The invoicing scope comes from your role.** Minting a token with `ecommerce:invoicing:issue` requires the permission to issue DTE in your Keebai role, unless you are the company owner or a superuser. See [scopes](/dev/scopes#scopes-are-independent-from-role-permissions).
</Note>

## Headers

| Header | Required | Value |
|---|---|---|
| `Authorization` | Yes | `Bearer kbai_pk_<token>` |
| `Content-Type` | Yes | `application/json` |
| `Idempotency-Key` | No | Your own unique key for this sale. Retrying with the same key does not create a second sale. |

## Body

| Field | Type | Required | Description |
|---|---|---|---|
| `type` | `string` | No | `sale` (default), a sale with payments, or `internal`, internal consumption: products only, no `payments`, no `dte`. |
| `branch_id` | `string` | Yes | Branch the sale happens in. Stock is deducted from it. |
| `items` | `object[]` | Yes | Line items. Every line is a catalog product. See below. |
| `customer` | `object` | No | `customer_id`, `name`, `email`, `phone`. |
| `seller` | `object` | No | `user_id` and `name`, both required when you send `seller`. |
| `payments` | `object[]` | No | Payments of the sale. See below. |
| `notes` | `string` | No | Free text. |
| `sold_at` | `string` | No | ISO 8601 date-time of the sale. |
| `currency` | `string` | No | Currency of the amounts. |
| `dte` | `object` | No | Issue the electronic tax document after creating the sale. See below. |

### Item

| Field | Type | Required | Description |
|---|---|---|---|
| `product_id` | `string` | Conditional | `ObjectId` of the product. Send `product_id` or `sku`. |
| `variant_id` | `string` | No | `ObjectId` of the variant. |
| `sku` | `string` | Conditional | SKU. Resolves the product and variant without sending `product_id`. Send `product_id` or `sku`. |
| `name` | `string` | No | Line name. Defaults to the product's. |
| `quantity` | `number` | Yes | Units. |
| `unit_price` | `number` | No | Unit price. Defaults to the product's. |
| `discount_percentage` | `number` | No | Discount on the line, in percent. |
| `commissionee` | `object` | No | Who earns the commission of the line: `id` and `name`. |

### Payment

| Field | Type | Required | Description |
|---|---|---|---|
| `method` | `string` | Yes | Payment method. |
| `amount` | `number` | Yes | Amount paid. |
| `reference` | `string` | No | External reference, such as a voucher number. |
| `installments` | `number` | No | Installments. |

### DTE

| Field | Type | Required | Description |
|---|---|---|---|
| `type` | `number` | Yes | `39` boleta, `41` boleta exenta, `33` factura, or `34` factura exenta. |
| `receiver` | `object` | Conditional | `rut`, `legal_name`, `activity`, `address`, `commune`, `email?`. Required for a factura (`33`, `34`). |

Check which types your company can issue today with [`GET /v1/ecommerce/invoicing/types`](/dev/endpoints/ecommerce-invoicing-types).

## Response

### 201 Created

`sale` has the same shape as [`GET /v1/ecommerce/sales/{id}`](/dev/endpoints/ecommerce-sale-get). `dte` is present only when you sent `dte`.

```json
{
  "sale": {
    "_id": "65e4f5a6b7c8d9e0f1a2b3c4",
    "sale_number": 1043,
    "status": "completed",
    "payment_status": "paid",
    "currency": "CLP",
    "items": [
      {
        "kind": "product",
        "name": "Zapatilla Runner Pro",
        "quantity": 1,
        "unit_price": 59990,
        "subtotal": 59990
      }
    ],
    "amounts": {
      "total": 59990
    },
    "branch_id": "br_01",
    "created_at": "2026-11-04T14:31:07.221Z"
  },
  "dte": {
    "issued": [
      {
        "sale_id": "65e4f5a6b7c8d9e0f1a2b3c4",
        "type": 39,
        "folio": 15422,
        "document_id": "6653e4f5a6b7c8d9e0f1a2b3",
        "status": "uploaded"
      }
    ],
    "failed": []

```

| Field | Type | Description |
|---|---|---|
| `sale` | `object` | The created sale. |
| `dte.issued[]` | `object[]` | Documents issued: `sale_id`, `type`, `folio`, `document_id`, `status`. |
| `dte.failed[]` | `object[]` | Documents that could not be issued: `sale_id`, `reason` (the error code), `message?`. The reasons are listed in [`POST /v1/ecommerce/sales/{id}/dte`](/dev/endpoints/ecommerce-sale-dte-issue#failure-reasons). |

### 400 Bad Request

The body does not match the schema, a field the endpoint does not accept, or one of these:

| `code` | Meaning |
|---|---|
| `SALE_ITEM_PRODUCT_REQUIRED` | A line has neither `product_id` nor `sku`. There are no free-text lines. |
| `INTERNAL_SALE_PAYMENTS_NOT_ALLOWED` | A `type: "internal"` sale carried `payments`. |
| `INTERNAL_SALE_DTE_NOT_ALLOWED` | A `type: "internal"` sale carried `dte`. |

### 401 Unauthorized

Missing, invalid, revoked, or expired token.

### 403 Forbidden

`INSUFFICIENT_SCOPE` — the token does not have `ecommerce:sales:write`, or it sent `dte` without `ecommerce:invoicing:issue`. Nothing is created.

### 422 Unprocessable Entity

| `code` | Meaning |
|---|---|
| `SKU_NOT_FOUND` | No product has that `sku`. |
| `SKU_AMBIGUOUS` | The `sku` matches more than one product. |
| `BRANCH_REQUIRED` | No `branch_id`. |
| `INVALID_PAYMENT` | A payment is not valid for the company — for example a method it does not accept. |
| `STOCK_INSUFFICIENT_IN_BRANCH` | The branch does not have enough stock for one of the items. |

### 502 Bad Gateway

`ECOMMERCE_UPSTREAM_ERROR` — the ecommerce service could not answer.

## Operational notes

- **Send an `Idempotency-Key` from a point of sale.** A timeout does not tell you whether the sale was created. Retrying with the same key returns `201` with the original sale and creates nothing new; without it, a retry can double the sale and the stock deduction.
- **SKUs are checked before anything is created.** `SKU_NOT_FOUND` and `SKU_AMBIGUOUS` leave no sale and no stock movement behind.
- **A failed confirmation leaves nothing behind.** If the sale cannot be confirmed — for example `INVALID_PAYMENT` or `STOCK_INSUFFICIENT_IN_BRANCH` — the cart is discarded and the error is returned.
- **A failed DTE does not undo the sale.** The sale stays created and the failure comes back in `dte.failed`. Fix the cause and issue it later with [`POST /v1/ecommerce/sales/{id}/dte`](/dev/endpoints/ecommerce-sale-dte-issue).
- **The DTE needs a paid sale.** A sale whose payments do not cover it fails the DTE with `unpaid`.
- **`internal` never issues a DTE.** Internal consumption has no payments and no tax document; it only moves stock.
- **Every line is a catalog product.** Send `product_id` or `sku`; with `sku` you do not need `product_id`. Without `unit_price` or `name`, the product's are used.
- **Commissions are calculated on the sale.** `commissionee` on a line decides who earns it.
